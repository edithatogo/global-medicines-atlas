# v0.7 fixture and production qualification

This evidence package classifies the governed-publication rehearsal; it does
not announce a release. The machine-readable source of truth is
[`release-inputs/v0.7-fixture-production-qualification.json`](../../release-inputs/v0.7-fixture-production-qualification.json),
validated by its adjacent JSON Schema.

The schema fixes the gate and state vocabulary structurally: each scope has
exactly one rights, privacy, provenance, software-licence, and maintainer
approval gate. Fixture scope can only be overall `passed` with its documented
fixture statuses; production scope can only be overall `blocked` with every
gate blocked. Publication state is an exact ordered set of `prepared`,
`uploaded`, and `public`: preparation is fixture-only, while upload and public
visibility are both `not_performed`.

## Publication state

- **Prepared:** passed for the synthetic fixture only.
- **Uploaded:** not performed. No GitHub, Hugging Face, or archive upload was
  attempted.
- **Public:** not performed. There is no public v0.7 dataset or release to

These states are deliberately independent. A prepared package is not evidence
of an upload, and an upload would not by itself prove public visibility.

## Source-specific redistribution boundaries

- Self-authored synthetic fixture rows are usable for local and CI rehearsal
  only and are excluded from any claim about production coverage.
- RxNorm payloads stay inside the licensed/local boundary required by M-052.
- NZMT, SNOMED CT, AMT, and other terminology payloads retain their own access,
  attribution, and redistribution terms.
- NZULM access does not establish a right to redistribute production bytes.
- Regulator and funder APIs, downloads, documents, and derived outputs require
  source-by-source review. Cataloguing an endpoint or retaining provenance does
  not grant publication rights.
- Metadata-only publication is also review-dependent; it is not automatically
  lawful merely because source payloads are omitted.

## Remaining production gates

Production remains fail-closed until all of the following refer to the exact
immutable release bytes:

1. source-specific rights and redistribution decisions;
2. privacy and forbidden-content review;
3. complete provenance, transformation, coverage, and uncertainty evidence;
4. an explicit software-licence decision by the copyright holder;
5. explicit maintainer approval for the identified release and destinations;
6. consumer verification of checksums, SBOM, and provenance attestations.
